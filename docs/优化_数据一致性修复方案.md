## 2. M1: 强制生成 DC + Analysis 双阶段

### 2.4 修改方案

```python
def _generate_phases(self, task_structure, intent, topic):
    phases = []
    counter = 1
    section_map = {s.section_id: s for s in task_structure.sections}
    global_section_to_agent = {}  # 跨 phase 的 section_id → agent_id 映射

    # === Phase 0: SURVEY（不变）===
    if intent.requires_primary_data:
        survey_sections = task_structure.sections[:1] if task_structure.sections else []
        phase = self._create_phase(f"phase_{counter}", PhaseType.SURVEY, survey_sections,
                                    task_structure, topic, parallel=False, depends_on=[],
                                    section_to_agent=global_section_to_agent)
        phases.append(phase)
        counter += 1

    # === 新增：收集 ANALYSIS section，拆分为 DC + Analysis 两个阶段 ===
    dag_layers = task_structure.parallel_groups
    if not dag_layers and task_structure.sections:
        dag_layers = [[s.section_id for s in task_structure.sections]]

    dc_sections = []       # 需要先生成 DC 阶段的 section
    analysis_sections = [] # 需要后生成 Analysis 阶段的 section
    other_phases = []      # 非 ANALYSIS 角色的 section（SYNTHESIS/SUPPORTING 等），保持原逻辑

    for layer_ids in dag_layers:
        for sid in layer_ids:
            section = section_map.get(sid)
            if not section:
                continue
            if section.section_role == SectionRole.ANALYSIS:
                dc_sections.append(section)
                analysis_sections.append(section)
            elif section.section_role == SectionRole.SYNTHESIS:
                other_phases.append(("synthesis", section))
            else:
                other_phases.append(("other", section))

    # Phase A: DATA_COLLECTION — 所有 ANALYSIS section 先做纯搜索
    if dc_sections:
        dc_phase = self._create_data_collection_phase(
            f"phase_{counter}", dc_sections, task_structure, topic,
            section_to_agent=global_section_to_agent,
        )
        phases.append(dc_phase)
        counter += 1

    # Phase B: DEEP_ANALYSIS — 基于已收集数据分析，依赖对应 DC agent
    if analysis_sections:
        analysis_phase = self._create_analysis_phase_with_deps(
            f"phase_{counter}", analysis_sections, task_structure, topic,
            section_to_agent=global_section_to_agent,
            depends_on=[dc_phase.phase_id] if dc_sections else [],  # v1.3: 显式传入 DC phase 依赖
        )
        phases.append(analysis_phase)
        counter += 1

    # Phase C: 处理其他角色的 section（SYNTHESIS 等）
    # ... 保持原有的 SYNTHESIS 逻辑

    # Phase D: REPORT（不变，始终最后）
    report_depends_on = [phases[-1].phase_id] if phases else []
    phases.append(self._create_report_phase(f"phase_{counter}", task_structure, topic,
                                             depends_on=report_depends_on))
    return phases
```

#### 新增 `_create_data_collection_phase()` 方法

```python
def _create_data_collection_phase(self, phase_id, sections, task_structure, topic,
                                   section_to_agent=None):
    """为 ANALYSIS section 创建纯数据收集阶段"""
    if section_to_agent is None:
        section_to_agent = {}
    agents = []
    for i, section in enumerate(sections):
        agent_id = f"{phase_id}_agent_{i}"
        agent = AgentSpec(
            agent_id=agent_id,
            agent_type="data_collection",  # PhaseType.DATA_COLLECTION.value
            section_ids=[section.section_id],
            priority=i,
            config={"content_dependency": []},  # DC 无依赖
            core_question=f"收集 {section.section_name} 维度的基础数据",
            section_role_desc="data_collection",
        )
        agents.append(agent)
        section_to_agent[section.section_id] = agent_id

    section_ids = [s.section_id for s in sections]
    return ExecutionPhase(
        phase_id=phase_id,
        phase_type=PhaseType.DATA_COLLECTION,
        agent_specs=agents,
        section_ids=section_ids,
        parallel=True,
        depends_on=[],
    )
```

#### 新增 `_create_analysis_phase_with_deps()` 方法

```python
def _create_analysis_phase_with_deps(self, phase_id, sections, task_structure, topic,
                                      section_to_agent=None, depends_on=None):
    """为 ANALYSIS section 创建分析阶段，每个 agent 依赖其对应的 DC agent"""
    if section_to_agent is None:
        section_to_agent = {}
    agents = []
    for i, section in enumerate(sections):
        agent_id = f"{phase_id}_agent_{i}"
        # 找到对应 DC agent 的 ID
        dc_dep = section_to_agent.get(section.section_id, [])
        agent = AgentSpec(
            agent_id=agent_id,
            agent_type=PhaseType.ANALYSIS.value,
            section_ids=[section.section_id],
            priority=i,
            config={"content_dependency": [], "resolved_dependencies": [dc_dep] if dc_dep else []},
            core_question=section.section_name,
            section_role_desc="analysis",
            dependencies=[dc_dep] if dc_dep else [],
        )
        agents.append(agent)
        # 更新映射（覆盖 DC 映射，后续 SYNTHESIS agent 用 Analysis agent ID）
        section_to_agent[section.section_id] = agent_id

    section_ids = [s.section_id for s in sections]
    return ExecutionPhase(
        phase_id=phase_id,
        phase_type=PhaseType.ANALYSIS,
        agent_specs=agents,
        section_ids=section_ids,
        parallel=True,
        depends_on=depends_on or [],  # v1.3 修正：不再引用外部 phases 变量
    )
```

> **v1.3 修正**：原方案 `depends_on=[phases[-1].phase_id] if phases else []` 引用了 `_generate_phases()` 的局部变量 `phases`，但 `_create_analysis_phase_with_deps()` 作为独立方法无法访问该变量。
> 修正为通过参数 `depends_on` 显式传入，在 `_generate_phases()` 调用时传入 `depends_on=[dc_phase.phase_id]`。
> 同理，`_generate_phases()` 中 Phase C 的 depends_on 也需显式传入 `analysis_phase.phase_id`。

### 2.6.1 DC agent 返回格式差异（v1.3 新增）

> **审查发现**：DC agent（`category="research"`）和 Analysis agent 的返回结构完全不同，`result_aggregator` 的现有逻辑只处理 `content` 字段。

**DC agent 返回结构**（`generic_agent.py:353-360`）：

```python
return self._ensure_standard_result({
    "success": True,
    "data_points": data_points,    # 搜索结果
    "sources": sources,            # 来源列表
    "total_sources": ...,
    "quality_stats": ...,
    "agent_id": self.agent_id,
}, action)
# 注意：无 "content" 字段！
```

**Analysis agent 返回结构**（`generic_agent.py:545-548`）：

```python
result["data_points"] = aggregated_data_points
result["sources"] = aggregated_sources
return self._ensure_standard_result(result, action)
# result["content"] = LLM 生成的分析文本
```

**聚合器处理逻辑**（`result_aggregator.py:977-999`）：

```python
# 只提取 content/result 字段作为章节内容
actual_content = None
if "content" in result and result["content"]:    # DC agent: "content" not in result → False
    actual_content = result["content"]
elif "result" in result and result["result"]:
    actual_content = str(result_val)              # DC agent: "result" not in result → False
# → DC agent 的 actual_content = None，不进入 layered_content

# 但 data_points/sources 通过 __meta key 传递：
if result.get("data_points"):
    meta_payload["data_points"] = result["data_points"]
    layered_content[stage][f"{agent_id}__meta"] = meta_payload   # DC 的 __meta 有 data_points
```

**影响分析**：

| 场景 | 结果 | 是否正确 |
|------|------|---------|
| DC agent 无 `content` → `_convert_to_sections()` 不匹配 DC agent | DC 的 data_points 通过 `__meta` key 传递到 Analysis agent | 正确（DC 是上游，不应生成章节内容） |
| Analysis agent 有 `content` → 匹配为章节正文 | 章节 content = Analysis agent 的 LLM 输出 | 正确 |
| `_convert_to_sections()` 的 `target_stages=["analysis", "data_collection"]` (line 320) | 优先取 `analysis` 层内容 | 正确（Analysis agent 在 analysis 层） |
| Analysis agent 的 `__meta` 包含 data_points + sources | 章节元数据（charts/data_points/sources）从 analysis 层的 `__meta` 提取 | 正确 |

**结论**：DC agent 返回格式差异**不影响最终报告生成**。DC agent 的 `data_points` 通过以下路径传递给 Analysis agent：

1. engine 批次 1 → DC agent 返回 `{data_points, sources}` → `all_results[agent_id]`
2. engine 批次 2 → Analysis agent 的 `previous_results` 包含 DC agent 的 `data_points`
3. engine 根据 `content_dependency` 过滤 `previous_results` → `filtered_data_points` 注入 task
4. Analysis agent 通过 `task["aggregated_data_points"]` 接收数据

**但有一个微妙点**：Analysis agent 的 `data_points` 来自上游过滤，可能不完整。DC agent 收集的 data_points 通过 `__meta` 也写入了 `layered_content["data_collection"]`，如果 `_convert_to_sections()` 错误地从 `data_collection` 层提取了 DC agent 的 `__meta`（而非从 `analysis` 层提取 Analysis agent 的 `__meta`），可能导致章节元数据不一致。M0-b 的 stage 分类修复可以确保 DC 和 Analysis agent 的 `__meta` 分别存储在正确的层中。

### 2.9 潜在问题与缓解

#### 问题 A: DC agent 的搜索结果可能不够全面

DC agent 的 `_do_deep_research()` 搜索时只知道 `section.section_name`（如"销量与市场份额"），不知道 Analysis agent 后续需要什么特定数据。

**缓解**：DC agent 的搜索关键词已经包含了 topic + aspect 的组合（`_do_deep_research()` 会基于 topic 和 aspect 构建搜索 query），与当前综合 agent 的搜索行为一致。搜索结果的质量不会降低。

#### 问题 B: ~~result_aggregator 聚合时 DC 和 Analysis 结果如何合并~~ → 严重 Bug：聚合 key 碰撞导致 DC 结果被覆盖

def _filter_data_by_aspect(self, data_points: List[Dict], aspect: str) -> List[Dict]:
    """按 aspect 关键词对 data_points 做相关性评分和过滤"""
    if not aspect:
        return data_points[:200]

    aspect_clean = aspect.replace("section_", "").replace("_", " ")
    aspect_keywords = set(aspect_clean.split())
    # 扩展同义词
    SYNONYM_MAP = {
        "财务": ["营收", "利润", "毛利率", "净利", "收入", "成本", "费用"],
        "销量": ["销量", "出货", "交付", "市场份额", "市占率"],
        "竞争": ["竞争对手", "竞争格局", "市场格局", "份额"],
        "研发": ["研发投入", "R&D", "专利", "技术创新"],
        "风险": ["风险", "负债", "现金流", "财务健康"],
        "国际化": ["海外", "出口", "国际化", "出海"],
        "预测": ["预测", "展望", "趋势", "前景"],
    }
    expanded_keywords = set(aspect_keywords)
    for kw in aspect_keywords:
        if kw in SYNONYM_MAP:
            expanded_keywords.update(SYNONYM_MAP[kw])

    scored = []
    for dp in data_points:
        dp_text = (dp.get("content", "") + " " + dp.get("title", "")).lower()
        overlap = sum(1 for kw in expanded_keywords if kw.lower() in dp_text)
        scored.append((overlap, dp))

    scored.sort(key=lambda x: -x[0])
    # 只保留有相关性的数据（overlap > 0）
    return [dp for score, dp in scored if score > 0][:500]
```

```python
def _enforce_canonical_values(self, content: str, canonical_data: Dict) -> str:
    """
    强制替换输出中与 canonical_data 不一致的数值。
    只对 MetricExtractor 定义的指标做替换，避免误替换。
    """
    import re as _re
    from src.core.data.metric_extractor import MetricExtractor

    if not canonical_data:
        return content

    extractor = MetricExtractor()
    found_metrics = extractor.extract([{"content": content, "url": ""}])

    replacements = []
    for fm in found_metrics:
        metric_name = fm["metric"]
        text_value = fm["value"]
        text_unit = fm["unit"]

        for key, entry in canonical_data.items():
            # canonical_data 格式: {"value": ..., "unit": ..., "caliber": ..., "source": ...}
            if not isinstance(entry, dict):
                continue

            # 匹配 metric name（key 格式: "metric_year_currency_caliber"）
            entry_metric = key.split("_")[0] if "_" in key else key
            if entry_metric != metric_name:
                continue

            canonical_value = entry.get("value")
            if canonical_value is None:
                continue

            # 允许 5% 误差
            diff = abs(text_value - float(canonical_value)) / max(abs(float(canonical_value)), 0.01)
            if diff > 0.05:
                replacements.append({
                    "metric": metric_name,
                    "old_value": text_value,
                    "new_value": canonical_value,
                    "unit": text_unit,
                })

    # 执行精确替换
    for r in replacements:
        old_str = str(r["old_value"])
        new_str = str(r["new_value"])
        metric = r["metric"]
        unit = r["unit"]

        # 只替换 "metric 附近 old_value unit" 的模式
        # 避免替换表格行中的数据（可能导致格式混乱）
        pattern = (
            rf'({_re.escape(metric)}'
            rf'[^\d]*?)'
            rf'({_re.escape(old_str)})'
            rf'(\s*{_re.escape(unit)})'
        )

        def _skip_table_line(match):
            # 检查 match 是否在 markdown 表格行中
            start = max(0, match.start() - 200)
            preceding = content[start:match.start()]
            # 如果前面最近的换行后是 | ，说明在表格行中
            last_newline = preceding.rfind('\n')
            if last_newline >= 0:
                line_start = preceding[last_newline:].lstrip('\n')
                if line_start.startswith('|'):
                    return match.group(0)  # 不替换
            return match.group(1) + new_str + match.group(3)

        content = _re.sub(pattern, _skip_table_line, content, count=1)

    if replacements:
        logger.info(
            f"GenericAgent {self.agent_id}: canonical 后处理替换了 {len(replacements)} 处数值"
        )

    return content
```

| SYNTHESIS 路径 (`generic_agent.py` line 613) | 同上 |

|------|------|------|---------|
| **正则误替换**：替换了不该替换的数字（如年份、页码、章节号） | 内容错误 | **中** | (1) 只对 `MetricExtractor` 定义的 12 种指标做替换 (2) 替换模式要求 `metric_name` 在数字前面 (3) 跳过 markdown 表格行 |
| **canonical_data 本身有误** | 正确值被错误值覆盖 | **低** | canonical_data 经过 `CaliberDecisionEngine` 仲裁，选择最高权威来源 |
| **多次替换导致文本不自然** | 可读性下降 | **低** | `count=1` 限制每个 metric 只替换第一次出现 |
| **精度不匹配**：canonical 是 `326.5`，文本是 `327`，替换后精度不自然 | 可读性轻微下降 | 低 | 保留文本原始精度格式 |
| **iterative deepening 后重新引入错误值** | 替换无效 | **中** | 需要在 iterative deepening 之后也执行一次替换 |
| **canonical_data 为空时** | 无替换，当前行为 | 确定 | 这是 M1 要解决的问题 |

### 4.6 需额外注意的点

#### iterative deepening 交互

`generic_agent.py:502-529` 的 iterative deepening 逻辑：
1. 第一次 LLM 调用 → 检测 knowledge gaps → 补充搜索 → 第二次 LLM 调用
2. 如果 M3 的替换只在第一次 LLM 后执行，deepening 的第二次调用会覆盖

**解决方案**：将 M3 的替换逻辑放在整个 DEEP_ANALYSIS 路径的最后（line 529 之后），确保 iterative deepening 完成后再做替换。

#### SYNONYM_MAP 的 metric_name 匹配

`canonical_data` 的 key 格式是 `"净利润_2025_CNY_A股口径"`（来自 `_entry_key()`），而 `MetricExtractor` 提取的 `metric_name` 是 `"净利润"`。匹配时需要从 key 中提取 metric 部分。

当前方案 `entry_metric = key.split("_")[0]` 对 `"净利润_2025_CNY_A股口径"` 能正确提取 `"净利润"`。但对于 `"海外销量_2025_CNY"` 这种包含 `_` 的 metric，`split("_")[0]` 只得到 `"海外"` 而不是 `"海外销量"`。

**缓解**：使用 `canonical_registry.py` 中已有的 `parse_entry_key()` 函数来解析 key，它能正确提取 metric 部分。

### 5.1 目标

# === M4: 数值级跨 agent 对账（新增在 line 1078 之后）===
from src.core.data.metric_extractor import MetricExtractor
_extractor = MetricExtractor()
_metric_conflicts: List[ConflictRecord] = []

# 从每个 agent 的内容中提取指标
all_agent_metrics: Dict[str, List[Dict]] = {}  # "metric_unit" -> [{agent_id, value, unit, year}]
for agent_id, result in results.items():
    content = ""
    if "content" in result and result["content"]:
        content = result["content"]
    elif "result" in result and result["result"]:
        content = str(result["result"])

    if not content or not isinstance(content, str):
        continue

    metrics = _extractor.extract([{"content": content, "url": ""}])
    for m in metrics:
        metric_key = f"{m['metric']}_{m.get('unit', '')}"
        all_agent_metrics.setdefault(metric_key, []).append({
            "agent_id": agent_id,
            "value": m["value"],
            "unit": m.get("unit", ""),
            "year": str(m.get("year", "")),
        })

# 按 metric + year 分组检测矛盾
for metric_key, entries in all_agent_metrics.items():
    if len(entries) < 2:
        continue

    by_year: Dict[str, List] = {}
    for e in entries:
        by_year.setdefault(e.get("year", ""), []).append(e)

    for year, year_entries in by_year.items():
        if len(year_entries) < 2:
            continue
        vals = [e["value"] for e in year_entries]
        max_val = max(abs(v) for v in vals) if vals else 0
        if max_val == 0:
            continue
        max_diff = max(vals) - min(vals)
        if max_diff / max_val > 0.05:  # > 5% 差异
            conflict = ConflictRecord(
                key=f"{metric_key}_{year}",
                values=vals,
                sources=[e["agent_id"] for e in year_entries],
                resolution=self.config.conflict_resolution,
                resolved_value=max(vals),  # 暂取最大值，后续可接入 CaliberDecisionEngine
            )
            _metric_conflicts.append(conflict)
            logger.warning(
                f"[M4] 数值冲突: {metric_key} (year={year}), "
                f"值={vals}, 来源={[e['agent_id'] for e in year_entries]}"
            )

# 合并到总冲突列表
conflicts.extend(_metric_conflicts)
stats["metric_conflicts"] = len(_metric_conflicts)
stats["metric_conflict_details"] = [
    {"key": c.key, "values": c.values, "sources": c.sources}
    for c in _metric_conflicts
]
```

#### 6.4.6 校准 Prompt 模板

```python
def _build_calibration_prompt(self, topic, analysis_content, data_points, canonical_data):
    """构建数据校准 prompt"""
    
    # 拼接所有分析内容
    content_sections = []
    for i, ac in enumerate(analysis_content):
        section_title = ac.get("title", f"章节{i+1}")
        section_text = ac.get("content", "")
        if section_text:
            content_sections.append(f"### {section_title}\n{section_text[:3000]}")
    
    # 拼接 canonical 数据
    canonical_lines = []
    for key, entry in canonical_data.items():
        canonical_lines.append(
            f"- {key}: {entry.get('value','')}{entry.get('unit','')} "
            f"(口径: {entry.get('caliber','不详')}, 来源: {entry.get('source','不详')})"
        )
    
    prompt = f"""# 数据校准任务

## 报告主题
{topic}

## 待校准内容
{chr(10).join(content_sections)}

## 已确认的规范数据
{chr(10).join(canonical_lines)}

## 校准要求

请对以上内容进行全面数据校准，输出以下内容：

### 1. 数值一致性检查
检查同一指标在不同章节中出现时，数值是否一致。列出所有矛盾：
- 指标名称
- 出现位置（章节）
- 各处的值
- 正确值（基于规范数据或最权威来源）
- 差异原因（如口径不同、时间维度不同）

### 2. 口径一致性检查
检查以下口径是否统一：
- 会计口径：归母净利润 vs 扣非净利润 vs 净利润
- 报表口径：合并报表 vs 母公司报表
- 时间口径：季度数据 vs 年度数据、FY vs CY
- 地域口径：全球销量 vs 中国销量 vs 海外销量

### 3. 叙述一致性检查
检查定性判断是否存在矛盾：
- 某章节说"大幅增长"，另一章节说"增速放缓"——是否有数据支撑矛盾？
- 某章节说"市场领先"，另一章节说"竞争激烈"——是否语境不同？
- 某章节引用的数据与另一章节描述的趋势是否吻合？

### 4. 货币和单位统一
列出所有涉及货币和单位的地方，确认是否统一。

### 5. 统一数据基准表（JSON 格式）
输出最终的统一数据基准表，格式如下：
```json
{{
  "净利润_2024": {{"value": xxx, "unit": "亿元", "caliber": "归母", "source": "..."}},
  "营收_2024": {{"value": xxx, "unit": "亿元", "caliber": "合并报表", "source": "..."}},
  "销量_2024": {{"value": xxx, "unit": "万辆", "caliber": "含出口", "source": "..."}},
  ...
}}
```

### 6. 修复建议
对每个发现的问题，给出具体的修复建议：
- 需要修改的章节
- 原文片段
- 建议修改为
- 修改原因
"""
    return prompt
```

### 7.3 英文正则设计

#### 单位模式

```python
_UNIT_CURRENCY_EN = r'billion\s+(?:CNY|USD|EUR|HKD|GBP|JPY)|million\s+(?:CNY|USD|EUR|HKD|GBP|JPY)|billion|million'
_UNIT_VOLUME_EN = r'million\s+(?:units|vehicles|cars)|thousand\s+(?:units|vehicles)|million|thousand'
```

`billion|million` 兜底匹配泛化单位，货币代码由 `_infer_currency()` 通过 `"CNY" in unit` 子串匹配推断。

#### 指标模式（12 种）

| 指标 | 中文 | 英文模式 |
|------|------|---------|
| 净利润 | 净利润/归母净利润/扣非净利润 | `net profit`, `net income` |
| 营收 | 营收/收入 | `revenue`, `total revenue`, `operating revenue`, `turnover` |
| 销量 | 总销量 | `(?<!overseas\s)(?:sales\|deliver(?:ies\|ed))`（负向 lookbehind 防重叠） |
| 海外销量 | 海外/出口销量 | `overseas sales`, `export sales`, `overseas deliveries` |
| 研发投入 | 研发投入/费用 | `R&D expense`, `R&D investment`, `research and development` |
| 毛利率 | 毛利率 | `gross margin`, `gross profit margin` |
| 市占率 | 份额 | `market share` |
| 增长率 | 增长率 | `growth rate` |
| 单车利润 | 单车利润 | `profit per vehicle`, `profit per unit` |
| 财务费用 | 财务费用 | `financial expense`, `finance costs` |
| 现金流 | 现金流 | `cash flow` |
| 负债率 | 负债率 | `debt ratio`, `debt-to-asset ratio`, `liability ratio` |

#### 关键防重叠设计

```
"overseas sales of 1.2 million vehicles"  → 海外销量 ✓
"sales of 4.25 million vehicles"           → 销量 ✓（因 (?<!overseas\s) 不匹配 overseas sales）
"BYD delivered 4.25 million vehicles"      → 销量 ✓
```

「海外销量」模式在前（line 39），「销量」模式在后（line 42）。`sales` 模式使用 `(?<!overseas\s)` 负向 lookbehind 防止与 `overseas_sales` 重叠匹配。

#### 数值小数兼容

英文数值使用小数点（如 `4.25`），`(\d+\.?\d*)` 同时匹配 `4`、`4.25`、`326`。

替换模式中 `(?:\\.0)?` 可选匹配解决中文整数 vs 英文小数形式：内容中有 `326.0` 时匹配 `326`。

`_enforce_canonical_values()` 和 `fix_content_from_canonical()` 的替换模式构建方式：

```python
# 之前：只匹配中文 metric 名
name_part = _re.escape(metric_name)
pattern = rf'({name_part}[^\d]*?)({old_pattern})(\s*{_re.escape(text_unit)})'

# 之后：同时匹配中英文别名
names = [metric_name] + en_aliases.get(metric_name, [])
name_part = "(?:" + "|".join(_re.escape(n) for n in names) + ")"
pattern = rf'({name_part}[^\d]*?)({old_pattern})(\s*{_re.escape(text_unit)})'

当 `text_unit` 为中文（如 "亿元"）时，英文别名替换模式的 `\s*{_re.escape(text_unit)}` 不会匹配英文内容的单位。此时 fallback 到值替换（`old_pattern` 匹配数字后仅替换数字部分，保留单位）。

## 8. 审查要点

### 9.0 自审发现总结（v1.1 新增）

v1.0 方案通过代码路径追踪验证，发现以下 3 处设计缺陷：

| # | 缺陷 | 严重度 | 影响 |
|---|------|--------|------|
| 1 | **聚合 key 碰撞**：`results_for_aggregation[section_id]` 导致同 section 的 DC + Analysis 结果互相覆盖 | **严重** | DC agent 数据在聚合前丢失，M1 完全无法工作 |
| 2 | **stage 分类失效**：`_extract_stage_from_agent_id()` 对 `phase_N_agent_M` 全部返回 `"data_collection"` | **严重** | layered_content 无法按 stage 分离 DC/Analysis 内容 |
| 3 | **v1.0 对 `_extract_stage_from_agent_id()` 的描述有误**：实际是关键字匹配返回 `"data_collection"` 默认值，而非返回整个 agent_id 字符串 | 中 | 问题 B 的缓解方案基于错误假设，需要重写 |

**修正措施**：新增 M0 前置修复（2.10 节），在 M1 之前先修复聚合通道。

### 9.0.1 外部审查遗漏发现（v1.3 新增）

v1.2 方案经逐行代码核对后，发现以下 4 处遗漏：

| # | 遗漏 | 严重度 | 涉及方案 | 修正位置 |
|---|------|--------|---------|---------|
| 1 | **M1 作用域 bug**：`_create_analysis_phase_with_deps()` 引用 `_generate_phases()` 的局部变量 `phases[-1]`，但作为独立方法无法访问 | **高** | M1 (§2.4) | §2.4 方法签名改为传入 `depends_on` 参数 |

### 9.1 M1 审查重点

1. **`_create_data_collection_phase()` 和 `_create_analysis_phase_with_deps()` 中的依赖关系是否正确？**
   - DC agent 的 `dependencies=[]` → 拓扑排序第一批
   - Analysis agent 的 `dependencies=[对应的 dc_agent_id]` → 拓扑排序第二批

2. **`global_section_to_agent` 映射的更新时序**
   - DC phase 创建时：`section.section_id → dc_agent_id`
   - Analysis phase 创建时：`section.section_id → analysis_agent_id`（覆盖 DC 映射）
   - 如果后续有 SYNTHESIS section，它的依赖会指向 Analysis agent（正确）

3. **`to_decomposition_plan()` 的 category 覆写是否完整？**
   - `ResearchPhase.DATA_COLLECTION` → `"research"` ✓
   - `ResearchPhase.DATA_VALIDATION` → `"quality-check"` ✓
   - `ResearchPhase.DEEP_ANALYSIS` → 保持 `spec.agent_type` ✓
   - 其他 ResearchPhase → 保持 `spec.agent_type` ✓

4. **`_extract_stage_from_agent_id()` 能否正确分类 `phase_1_agent_N` 和 `phase_2_agent_N`？**
   - 当前行为（`result_aggregator.py:863-883`）：关键字匹配，`phase_1_agent_0` 不含 "synthesis"/"analysis"/"data"/"collect"/"research" → 走 else → 返回 `"data_collection"`
   - 这导致 DC (`phase_1_agent_N`) 和 Analysis (`phase_2_agent_N`) 都被分类为 `"data_collection"`
   - **v1.3 修正方案**：从 `result["category"]` 读取（已由 `_ensure_standard_result()` 写入），见 §2.10.1

### 9.2 M2 审查重点

1. **`_filter_data_by_aspect()` 的同义词表是否足够覆盖？**
2. **过滤后为空时的降级策略是否安全？**（limit 200 的全量注入）
3. **SYNONYM_MAP 是否应该外置到配置文件？**

### 9.3 M3 审查重点

1. **替换位置：应该在 iterative deepening 之后还是之前？**（建议之后）
2. **`parse_entry_key()` 是否能正确解析所有 canonical key 格式？**
3. **跳过 markdown 表格行的逻辑是否可靠？**
4. **`count=1` 是否足够？如果同一指标在同一章节出现多次且不一致，只替换第一次**

### 9.4 M4 审查重点

1. **`MetricExtractor` 对中文文本的提取准确率如何？**（基于 `METRIC_PATTERNS` 的 12 种正则）
2. **5% 的差异阈值是否合理？**（有些指标如市占率差异 35% vs 90% 远超 5%，但有些如净利润 326 vs 330 可能是四舍五入）
3. **`by_year` 分组是否可靠？**（`_infer_year()` 只在 100 字窗口内查找年份，可能漏判）
4. **`resolved_value=max(vals)` 是否合理？**（应该用 `CaliberDecisionEngine` 仲裁）

### 9.5 M5 审查重点（v1.4 新增）

1. **M5-a 规则层的 content 替换是否安全？** 与 M3 使用相同的替换逻辑，需确认 count=1 是否足够
2. **校准 Agent 的 prompt 是否过长？** 8 章节 × 3000 字截断是否足够覆盖关键数据点
3. **LLM 校准 Agent 的"建议"是否可靠？** Agent 只输出建议不直接修改 content，Report agent 是否会遵循
4. **`unified_data_reference` 注入 Report agent 的路径是否完整？** 需确认 Report agent 的 prompt 模板支持
5. **校准 Agent 的 `category="calibration"` 在 `_create_agents_from_plan()` 中是否正确路由 skill？** 需确认 `ASPECT_SKILL_MAP` 是否需要新增 "Data Calibration" 条目
6. **PhaseType.CALIBRATION 在所有映射表中是否完整？** `phase_type_to_research_phase`、`execution_order`、`_role_to_phase_type()` 等

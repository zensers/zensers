# 数据重复问题根因分析与解决方案

## 一、根因链

```
75% 数据重复的完整因果链：

1. 任务分解
   └── 8 个 phase_1 agent，全部 depends_on=[]
   └── 拓扑排序 → 所有 8 个 agent 分到同一个 batch（batch 0）
       → 8 个 agent 完全并行，无前后依赖

2. 搜索阶段（每个 agent 独立搜索）
   └── generic_agent.py:1368 → _generate_search_queries(topic, aspect, ...)
   └── 搜索查询包含 topic 关键词（"比亚迪"），但 aspect 差异化不足
   └── 例：
       ├── agent_0 (国际化与出口): "比亚迪 出口 2026" / "BYD overseas sales"
       ├── agent_4 (销量与市场份额): "比亚迪 销量 2026" / "BYD sales volume"
       ├── agent_2 (核心财务指标): "比亚迪 营收 2026" / "BYD revenue"
       └── 但核心搜索 "比亚迪 2026 财报" 被 8 个 agent 都搜索了
   └── 结果：8 个 agent 搜索到大量相同的网页和数据

3. 数据注入（关键问题所在！）
   └── engine.py:2075-2095 的 fallback 路径：
       if not filtered_data_points and not filtered_sources:
           # 从 ResearchResultStore 加载全量数据
           saved_dps = saved.get("data_points", [])
           task["aggregated_data_points"] = deduped[:5000]  # 全量 5000 条！
   └── 所有 8 个 agent 的 depends_on=[] → filtered_data_points 为空
   └── → 全部走了 fallback → 全部拿到了全量 data_points
   └── 即使有依赖过滤的路径（line 2004-2023），也被跳过了

4. LLM 分析（每个 agent 看到相同数据）
   └── 8 个 agent 的 prompt 中包含相同的 531 个 data_points
   └── prompt 中 canonical_data 也相同（来自同一 SharedMemory）
   └── LLM 从相同数据中提取相同结论 → 输出重复内容

5. 聚合（无去重）
   └── result_aggregator 按 agent_id 存储，不检查内容重复
   └── 8 份文本直接拼接到最终报告
```

## 二、重复的三个层次

| 层次 | 原因 | 占比估算 |
|------|------|:--------:|
| **搜索层重复** | 8 个 agent 搜索到相同的网页 | ~30% |
| **数据注入重复** | 全量 data_points 发给所有 agent | ~40% |
| **分析层重复** | LLM 从相同数据得出相同结论 | ~30% |

## 三、解决方案设计

### 方案 G：数据分配调度（Data Partitioning）

**核心思路**：不再把全量 data_points 发给每个 agent，而是按 aspect 关键词分配。

#### 3.1 搜索层：查询去重

```
当前：8 个 agent 各自搜索 "比亚迪 2026 财报" → 重复
改后：搜索前置为公共阶段，所有查询词去重后再分配
```

**实现位置**：engine.py `execute_with_scheduler()`

```python
# 新增：在 batch 执行前收集所有 agent 的搜索查询词
all_queries = set()
for agent in batch_agents:
    queries = agent._generate_search_queries(topic, aspect, ...)
    all_queries.update(queries)

# 按相关性分配给各 agent（而非全量）
for agent in batch_agents:
    relevant_queries = [q for q in all_queries if _is_relevant(q, agent.aspect)]
    agent._assigned_queries = relevant_queries
```

**问题**：这需要大改搜索架构（从 agent 内搜索变为 engine 层统一搜索），侵入性太高。

**替代方案**：不改搜索层，改为在数据注入层过滤。

#### 3.2 数据注入层：按 aspect 过滤 data_points（推荐实现）

**核心改动**：在 engine.py:2075 的 fallback 路径中，按 agent 的 aspect 过滤 data_points。

```python
# 当前 (engine.py:2075-2095)
if not filtered_data_points and not filtered_sources:
    saved_dps = saved.get("data_points", [])
    task["aggregated_data_points"] = deduped[:5000]  # 全量

# 改后
if not filtered_data_points and not filtered_sources:
    saved_dps = saved.get("data_points", [])
    # 按 aspect 相关性过滤
    agent_aspect = getattr(agent, 'section_id', '') or self._extract_aspect_from_agent_id(agent.agent_id)
    if agent_aspect:
        relevant_dps = self._filter_data_points_by_aspect(saved_dps, agent_aspect)
        task["aggregated_data_points"] = relevant_dps[:2000]  # 降半
    else:
        task["aggregated_data_points"] = deduped[:5000]
```

**`_filter_data_points_by_aspect` 实现**：

```python
def _filter_data_points_by_aspect(self, data_points: List[Dict], aspect: str) -> List[Dict]:
    """按 aspect 关键词相关性过滤 data_points"""
    aspect_keywords = self._extract_aspect_keywords(aspect)
    
    scored = []
    for dp in data_points:
        content = (dp.get("content", "") + " " + dp.get("title", "")).lower()
        # 计算相关性分数
        relevance = sum(1 for kw in aspect_keywords if kw in content)
        if relevance > 0:
            scored.append((relevance, dp))
        else:
            scored.append((0, dp))  # 保留无关数据但优先级低
    
    # 排序：高相关性在前，同时保留一定比例的低相关性数据作为补充
    scored.sort(key=lambda x: x[0], reverse=True)
    
    high_rel = [dp for score, dp in scored if score > 0]
    low_rel = [dp for score, dp in scored if score == 0]
    
    # 80% 高相关 + 20% 补充数据（避免信息孤岛）
    total = min(len(scored), 2000)
    high_count = int(total * 0.8)
    return high_rel[:high_count] + low_rel[:total - high_count]
```

**关键词提取**（从 aspect 名称和 agent 配置中提取）：

```python
ASPECT_KEYWORD_MAP = {
    "核心财务指标与盈利能力": ["营收", "利润", "毛利率", "净利率", "ROE", "现金流", "财报"],
    "研发与创新投入": ["研发", "R&D", "专利", "技术", "创新"],
    "供应链成本效率": ["供应链", "成本", "原材料", "零部件", "供应商"],
    "销量与市场份额": ["销量", "份额", "市占率", "交付", "出货"],
    "国际化与出口": ["出口", "海外", "国际", "境外", "global"],
    "财务健康": ["负债", "风险", "偿债", "流动性", "评级"],
    "行业对标与竞争格局": ["竞争", "对标", "特斯拉", "蔚来", "理想", "行业"],
    "财务预测": ["预测", "预期", "展望", "目标价", "forecast"],
}

def _extract_aspect_keywords(self, aspect: str) -> List[str]:
    for key, keywords in ASPECT_KEYWORD_MAP.items():
        if any(k in aspect for k in key.split("与")):
            return keywords
    # fallback: 从 aspect 名称中提取关键词
    return [w for w in aspect.split("与") if len(w) >= 2]
```

#### 3.3 分析层：Prompt 指令去重

在 aspect-specific prompt 中增加：

```
**重要**：你的分析必须聚焦于"{aspect}"维度。其他维度（如{other_aspects}）的分析
由其他 agent 负责，你不得重复这些内容。如果你的分析中包含其他维度的核心数据，
请仅作为交叉引用的辅助证据，不超过总篇幅的 15%。
```

### 方案 H：两阶段执行架构（长期方案）

**核心思路**：将 8 个并行 agent 的全量搜索改为"先统一搜索，再分配数据"。

```
当前架构：
  8 agents (parallel, all search + all analyze)
  → 每个 agent 独立搜索 → 独立分析 → 重复

改后架构：
  Phase 0: 1 个 Data Collection Agent
           → 统一搜索 → 去重 → 写入 ResearchResultStore
  Phase 1: 8 个 Analysis Agent (parallel)
           → 从 ResearchResultStore 读取
           → 按 aspect 过滤分配
           → 各自分析（不再搜索）
  Phase 2: Synthesis
```

**优势**：
1. 搜索只做一次，彻底消除搜索层重复
2. data_points 按 aspect 分配，每个 agent 只看相关数据
3. 节省 8x 搜索 API 调用成本

**限制**：
1. 需要大改调度架构（从 1-batch 变为 2-batch）
2. 增加总延迟（Phase 0 串行）
3. Data Collection Agent 需要知道所有 aspect 的搜索需求

## 五、实施建议

### 优先级：G（数据注入层过滤）> H（两阶段架构）

**理由**：
- G 改动范围小（仅 engine.py 一个方法 + 关键词映射），风险低
- G 见效快（改完立即生效）
- H 是架构级改动，应放到后续迭代

### G 的实施步骤

1. 在 engine.py 中新增 `_filter_data_points_by_aspect()` 方法
2. 在 engine.py:2075 的 fallback 路径中调用过滤
3. 定义 `ASPECT_KEYWORD_MAP` 关键词映射
4. 测试：确保过滤后的 data_points 仍足够支撑分析质量
5. 调参：调整 80%/20% 的比例和 max 限制

### 风险点

1. **信息孤岛**：过度过滤可能导致 agent 缺少必要的交叉信息
   - 缓解：保留 20% 补充数据 + canonical_data 不受过滤影响
2. **关键词映射维护**：不同主题需要不同的关键词映射
   - 缓解：提供 fallback（从 aspect 名称自动提取关键词）
3. **过滤过激**：某些 agent 可能需要看似不相关的数据
   - 缓解：设置最低 data_points 数量阈值（如 min 100 条）

## A1+A3: 评分归一化统一层

### 问题

当前评分归一化是散点启发式：

```
engine.py:2544  if 0.0 <= score < 1.0: score = score * 100.0
content_lock.py:289-290  if threshold_100 <= 1.0: threshold_100 = threshold_100 * 100.0
content_lock.py:334-335  (同上重复)
```

三个问题：
1. **歧义**: `0.5` 是 0.5分/100 还是 0-1尺度的 50%？无法区分
2. **重复**: content_lock 相同逻辑写两遍
3. **分散**: 没有统一的入口函数

### 设计

#### 新建: `src/core/quality/normalizer.py`

```python
from typing import Optional, Literal

def normalize_quality_score(
    score: Optional[float],
    source_scale: Optional[Literal["0-1", "0-100"]] = None,
    default: float = 50.0,
) -> float:
    """
    统一评分归一化入口。

    Args:
        score: 原始分数，None 时返回 default
        source_scale: 显式标注分数尺度
            "0-1"   → 乘以 100（0.5 → 50.0）
            "0-100" → 原值返回
            None    → 自动检测（保留向后兼容）
        default: score 为 None 时的默认值

    Returns:
        归一化后的分数，clamp 到 [0, 100]

    自动检测规则:
        - None → default
        - 0.0 <= score < 1.0 → 乘以 100（匹配 engine.py:2544 原始行为）
        - score >= 1.0 → 原值返回（1.0 本身不被放大）
        - score < 0 → clamp 到 0
        - score > 100 → clamp 到 100

    注意:
        score=1.0 不被放大（与 engine 原始行为一致）。
        如果调用者需要将 1.0 视为 0-1 尺度的满分，必须显式传入 source_scale="0-1"。
        content_lock 的 _normalize_threshold 另有一套规则（1.0 → 100.0），
        两者行为一致地保留了各自的原始语义。
    """
    if score is None:
        return max(0.0, min(100.0, default))

    # 显式标注优先
    if source_scale == "0-1":
        normalized = score * 100.0
    elif source_scale == "0-100":
        normalized = score
    else:
        # 自动检测（匹配 engine.py:2544 原始行为：仅 [0, 1.0) 被放大）
        if 0.0 <= score < 1.0:
            normalized = score * 100.0
        else:
            normalized = score  # score >= 1.0 原值返回

    return max(0.0, min(100.0, normalized))
```

## A2: content_lock 阈值规范化

### 问题

`content_lock.py:285-295` 和 `:330-340` 有完全相同的阈值放大逻辑：

```python
threshold_100 = rule.quality_threshold
if threshold_100 <= 1.0:
    threshold_100 = threshold_100 * 100.0
if required_status.quality_score < threshold_100:
    return False, ...
```

并且 `quality_threshold=1.5` 不会被放大（>1.0），也不会告警。

### 设计

#### 在 `ContentLockManager` 中新增方法

```python
def _normalize_threshold(self, threshold: float) -> float:
    """
    将阈值归一化到 0-100 尺度。

    规则:
        - 负数 → raise ValueError
        - (0, 1.0) → warning 提示将自动放大
        - [0, 1] → 乘以 100（兼容 0-1 尺度旧配置）
        - > 1 → 原值返回
    """
    if threshold < 0:
        raise ValueError(f"Negative threshold: {threshold}")

    if 0 < threshold < 1.0:
        logger.warning(
            f"quality_threshold={threshold} is a fractional value, "
            f"auto-scaling to {threshold * 100.0:.1f} (0-100 scale)"
        )

    if 0.0 <= threshold <= 1.0:
        return threshold * 100.0

    return threshold
```

#### 替换两处重复逻辑

将 `content_lock.py:285-295` 和 `:330-340` 中各替换为：

```python
if rule.lock_type in ("quality_threshold", "both"):
    threshold_100 = self._normalize_threshold(rule.quality_threshold)
    if required_status.quality_score < threshold_100:
        return False, (
            f"Required section {required_id} quality "
            f"{required_status.quality_score:.2f} < threshold {threshold_100:.2f}"
        )
```

#### 与外部队调用者的关系

`_normalize_threshold` 是私有方法，仅被 `ContentLockManager` 内部调用（`_check_section_locks` 和 `_try_unlock`）。不需要修改对外接口。

## A4: 方法论注入扩容

### 问题

`generic_agent.py:2913-2915`：

```python
methodologies = enrichment.get("methodologies", [])
if methodologies:
    base += f"\n\n## 分析框架\n{methodologies[0]['content'][:150]}\n"
```

缺陷：
1. 仅取 `methodologies[0]`，第 2、第 3 个框架被丢弃
2. `[:150]` 截断：Porter's Five Forces 需 ~200 字符，150 不够

### 设计

```python
methodologies = enrichment.get("methodologies", [])
if methodologies:
    methodology_summaries = []
    for i, m in enumerate(methodologies[:3]):  # ← 最多 3 个
        content = m.get('content', '')
        if content:
            # 多 key 回退链: name > methodology_name > title > 默认
            name = m.get('name') or m.get('methodology_name') or m.get('title') or f'框架{i+1}'
            # 每个框架截断 300 字符，比原来 150 翻倍
            truncated = content[:300]
            methodology_summaries.append(f"{i+1}. {name}: {truncated}")

    if methodology_summaries:
        base += "\n\n## 分析框架\n" + "\n\n".join(methodology_summaries) + "\n"
```

**改动效果**:

| 维度 | 修改前 | 修改后 |
|------|--------|--------|
| 框架数量 | 1 个 | 最多 3 个 |
| 单个预算 | 150 chars | 300 chars |
| 总预算 | 150 chars | ≤ 900 chars |
| 格式 | `{content[:150]}` | `1. 名称: {content[:300]}` |

**风险控制**:
- `methodologies` 为空 → 跳过（无框架节）
- 单个方法论无 `content` key → `get('content', '')` 安全
- 总字符 ≤ 900，在典型 3000-5000 字符 prompt 中的占比 < 20%

## A5: 融合权重配置化

### 问题

`quality_check_agent.py:262`：

```python
quality_score = quality_score * 0.6 + section_overall * 0.4
```

权重硬编码，不能随报告类型调整。

### 设计

#### 在 `QualityCheckAgent` 中增加类常量

```python
class QualityCheckAgent(FixedAgent):
    """质量检查 Agent"""

    # 融合权重（注意: QualityCheckAgent 不是 dataclass，
    # 使用普通类变量而非 field()）
    FUSION_WEIGHTS: Dict[str, float] = {
        "quality_score": 0.6,
        "section_overall": 0.4,
    }
```

#### 读取权重的私有方法

```python
def _get_fusion_weights(self) -> Dict[str, float]:
    """
    获取融合权重，优先使用 config 中的配置。

    config 格式:
        config["fusion_weights"] = {"quality_score": 0.5, "section_overall": 0.5}
    """
    # 从 session config 读取
    config_weights = self.config.get("fusion_weights", None)

    if isinstance(config_weights, dict):
        # 验证权重和是否为 1.0
        total = sum(config_weights.values())
        if abs(total - 1.0) < 0.01:
            return config_weights
        else:
            logger.warning(
                f"Fusion weights {config_weights} sum to {total}, "
                f"expected 1.0. Using defaults."
            )

    # 回退到类常量
    return dict(self.FUSION_WEIGHTS)
```

#### 替换融合公式位置

```python
# quality_check_agent.py:262 — 修改前
quality_score = quality_score * 0.6 + section_overall * 0.4

# 修改后
weights = self._get_fusion_weights()
quality_score = (
    quality_score * weights["quality_score"]
    + section_overall * weights["section_overall"]
)
```

#### 调用链影响

`_get_fusion_weights()` 仅在 `QualityCheckAgent.calculate_final_score()`（或对应融合位置）调用一次。不影响其他方法。

## A7: Agent 自评指令

### 问题

`quality_rubric.md` 已注入所有 24 个 agent prompt（v9.2 完成），但 agent 不读取也不使用 rubric 做自我评估。`execute()` 没有自评步骤。

### 设计

#### 新增辅助函数与 `GenericAgent` 方法

v9.2 通过 `{include:quality_rubric}` 在 prompt 加载时将 `prompts/_shared/quality_rubric.md`
解析为文本（`PromptManager._resolve_includes()`），不存入 `_context`。
因此自评需要直接读取 rubric 文件。

```python
import json
import re
from pathlib import Path

# 读取 rubric 文件（模块级缓存，避免重复 IO）
_RUBRIC_CACHE: str = ""

def _load_quality_rubric() -> str:
    """读取 quality_rubric.md 文件内容"""
    global _RUBRIC_CACHE
    if not _RUBRIC_CACHE:
        # __file__ = src/core/agents/generic_agent.py
        # 需要 4 级 parent 回到项目根: src/ → src/../ (回到 root)
        rubric_path = Path(__file__).parent.parent.parent.parent / "prompts" / "_shared" / "quality_rubric.md"
        if rubric_path.exists():
            _RUBRIC_CACHE = rubric_path.read_text(encoding="utf-8")
        else:
            _RUBRIC_CACHE = ""
    return _RUBRIC_CACHE


class GenericAgent:
    # ... 现有代码 ...

    async def _self_evaluate(self, content: str) -> Dict[str, Any]:
        """
        对生成的分析内容进行自我质量评估。

        仅在以下条件全部满足时执行:
            1. quality_rubric.md 文件存在
            2. 内容长度 > 500 字符（避免短文本无意义自评）

        注: `_call_llm_directly` 返回 {"success": True, "content": "..."}，
        不是纯字符串。

        Returns:
            {"score": int, "weak_dimensions": List[str], "suggestions": List[str]}
            或 rubric 不存在时返回 {"pass": True, "score": 100}
        """
        if len(content) < 500:
            return {"pass": True, "score": 100}

        rubric = _load_quality_rubric()
        if not rubric:
            return {"pass": True, "score": 100}

        eval_prompt = (
            f"请根据以下评分标准对分析内容进行质量评估（0-100 分）。\n\n"
            f"## 评分标准\n{rubric}\n\n"
            f"## 分析内容（前 3000 字符）\n{content[:3000]}\n\n"
            f"请以 JSON 格式输出：\n"
            f'{{"score": <0-100>, '
            f'"weak_dimensions": ["维度1", "维度2"], '
            f'"suggestions": ["改进建议1", "改进建议2"]}}'
        )

        resp = await self._call_llm_directly(
            prompt=eval_prompt,
            temperature=0.2,
            max_tokens=1000,  # 比默认 500 翻倍，确保完整 JSON 输出
        )

        # _call_llm_directly 返回 {"success": True, "content": "..."}
        if not resp.get("success"):
            return {"pass": True, "score": 100, "llm_error": resp.get("error")}

        result_text = resp.get("content", "")

        # 解析 JSON 响应
        try:
            parsed = json.loads(result_text)
            if isinstance(parsed, dict) and "score" in parsed:
                return parsed
        except (json.JSONDecodeError, ValueError):
            pass

        # 尝试从 markdown 代码块中提取
        match = re.search(r'```(?:json)?\s*(\{.*?\})\s*```', result_text, re.DOTALL)
        if match:
            try:
                parsed = json.loads(match.group(1))
                if isinstance(parsed, dict) and "score" in parsed:
                    return parsed
            except (json.JSONDecodeError, ValueError):
                pass

        return {"pass": True, "score": 100, "parse_error": True}
```

在深度分析路径末尾（`generic_agent.py:481-509` 附近），迭代深化块之后：

```python
# --- 迭代深化 ---

    gaps = self._detect_knowledge_gaps(result["content"])
```

## A8: hibernate 持久化清理

### 问题

`factory.py:clear_registry()` 清理了 `_agents` dict 和 `_session_registries`，但不清理磁盘上已 hibernate 的 session 文件。长期运行产生磁盘泄露。

### 设计

#### 在 `SessionPersistenceManager` 中新增方法

```python
def delete_session(self, session_id: str) -> bool:
    """
    删除指定 session 的持久化文件。

    删除顺序:
        1. sessions/agents/{session_id}.json
        2. results/{session_id}/ 目录
    （不删除 registry 文件，registry 由 cleanup_completed_session 管理）

    Args:
        session_id: Session ID

    Returns:
        是否成功删除（文件存在且删除成功）
    """
    deleted = False

    # 删除 session 文件
    # 注意: self.sessions_dir = self.storage_path / "sessions" / "agents"
    session_path = self.sessions_dir / f"{session_id}.json"
    if session_path.exists():
        try:
            session_path.unlink()
            logger.debug(f"Deleted hibernate session file: {session_id}")
            deleted = True
        except OSError as e:
            logger.warning(f"Failed to delete session file {session_id}: {e}")

    # 删除 results 文件（单文件格式，非目录）
    # 实际存储: self.results_dir / "{session_id}_result.json"
    # 参见 session_persistence.py:122 save_result()
    result_path = self.results_dir / f"{session_id}_result.json"
    if result_path.exists():
        try:
            result_path.unlink()
            logger.debug(f"Deleted hibernate result file: {session_id}")
            deleted = True
        except OSError as e:
            logger.warning(f"Failed to delete result file {session_id}: {e}")
    
    # 同时尝试清理旧版目录格式（兼容遗留数据）
    legacy_dir = self.results_dir / session_id
    if legacy_dir.exists():
        try:
            import shutil
            shutil.rmtree(legacy_dir)
            logger.debug(f"Deleted legacy results dir: {session_id}")
            deleted = True
        except OSError as e:
            logger.warning(f"Failed to delete legacy results {session_id}: {e}")

    return deleted
```

#### 修改 `factory.py:clear_registry()` — 在 del 前获取 session_id

```python
def clear_registry(self, parent_session_id: str) -> bool:
    """清理指定父 Session 的 Registry"""
    if parent_session_id in self._session_registries:
        registry = self._session_registries[parent_session_id]
        agent_ids_to_remove = []
        for agent_id, agent in list(self._agents.items()):
            session = getattr(agent, '_session', None)
            if session and getattr(session, 'parent_session_id', None) == parent_session_id:
                agent_ids_to_remove.append(agent_id)

        for aid in agent_ids_to_remove:
            agent_obj = self._agents[aid]
            # 在 del 前获取 session_id，用于清理持久化文件
            if self._persistence and hasattr(self._persistence, 'delete_session'):
                session_id = getattr(getattr(agent_obj, '_session', None), 'session_id', None)
                if session_id:
                    try:
                        self._persistence.delete_session(session_id)
                    except Exception as e:
                        logger.warning(f"Failed to delete hibernate data for {session_id}: {e}")
            del self._agents[aid]

        registry.clear()
        del self._session_registries[parent_session_id]
        if agent_ids_to_remove:
            logger.debug(f"清理 {len(agent_ids_to_remove)} 个 agent: {agent_ids_to_remove}")
        return True
    return False
```

**关键点**:
- `session_id` 来自 `agent._session.session_id`（不是 `agent_id`），因为 hibernate 持久化使用 session_id 作为文件名
- 必须在 `del self._agents[aid]` **之前**获取 session_id
- `hasattr` + `try/except` 双重安全防护

## A9: S1 缺口检测语义升级

### 问题

`generic_agent.py:_detect_knowledge_gaps(:1892-1933)` 仅做 4 项启发式字符统计：

| 检查 | 方法 | 局限 |
|------|------|------|
| 定量数据 | `re.findall(r'\d+[\.\d]*%...')` < 5 | 不检查数据是否支撑论点 |
| 年份引用 | `re.findall(r'\d{4}')` < 3 | 不检查年份是否与语境相关 |
| 内容长度 | `len(content)` < 1500 | 长文本也可能空洞 |
| 趋势关键词 | `keyword in content` < 3 | 关键词存在 ≠ 趋势分析 |

位于 async 上下文）在启发式触发后调用。

#### 新增异步语义检查（在 execute() 的迭代深化块中调用）

```python
async def _detect_semantic_gaps(self, content: str) -> List[str]:
    """
    使用 LLM 检测语义级别的知识缺口。（异步方法）

    仅在启发式检查已触发缺口时调用（成本控制）。

    注: `_call_llm_directly` 返回 {"success": True, "content": "..."}，
    不是纯字符串。

    检查维度:
        1. 结构要素完整性: 是否覆盖核心判断/数据支撑/逻辑推导/反证/含义
        2. 反证/边界条件: 是否有"如果...则..."/风险/不确定性讨论

    Returns:
        List[str]: 语义缺口描述（最多 2 项）
    """
    # 400 字符摘要以控制 token 消耗
    summary = content[:400]

    prompt = (
        "分析以下研究内容，检测知识缺口。以 JSON 格式输出。\n\n"
        "## 检查维度\n"
        "1. 结构完整性：是否包含核心判断、数据支持、逻辑推导、"
        "反证分析、投资含义五个要素？\n"
        "2. 反证覆盖：是否讨论了风险、边界条件、替代情景？\n\n"
        "## 内容\n"
        f"{summary}\n\n"
        "## 输出格式\n"
        '{"gaps": ["缺口描述1", "缺口描述2"], '
        '"has_structure": true/false, '
        '"has_counter_evidence": true/false}'
    )

    resp = await self._call_llm_directly(
        prompt=prompt,
        temperature=0.2,
    )

    # _call_llm_directly 返回 {"success": True, "content": "..."}
    if not resp.get("success"):
        return []

    result_text = resp.get("content", "")

    # 解析 JSON
    import json, re
    try:
        parsed = json.loads(result_text)
        if isinstance(parsed, dict):
            gaps = parsed.get("gaps", [])
            return gaps[:2]
    except (json.JSONDecodeError, ValueError):
        pass

    # markdown 代码块回退
    match = re.search(r'```(?:json)?\s*(\{.*?\})\s*```', result_text, re.DOTALL)
    if match:
        try:
            parsed = json.loads(match.group(1))
            if isinstance(parsed, dict):
                return parsed.get("gaps", [])[:2]
        except (json.JSONDecodeError, ValueError):
            pass

    return []
```

| 场景 | 启发式是否触发 | LLM 是否调用 | 每次调用的 token 估计 |
|------|---------------|-------------|---------------------|

| 短内容（>1 gap） | ✅ 2+ gaps | ✅ | ~600 |
| 空/极短内容 | ✅ 提前返回 | ❌ | 0 |

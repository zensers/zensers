### A1 normalize_quality_score() 统一函数 (4h)

**问题**: 当前散点启发式 `if 0.0 <= score < 1.0` 无法区分"0.5分/100"和"50%/0-1尺度"

**方案**:
```python
# src/core/quality/normalizer.py (新建)
def normalize_quality_score(
    score: float,
    source_scale: Optional[Literal["0-1", "0-100"]] = None,
    default: float = 50.0,
) -> float:
    if source_scale == "0-1":
        return score * 100.0
    if source_scale == "0-100":
        return score
    # 自动检测 (保留兼容)
    if 0.0 <= score <= 1.0:
        return score * 100.0
    return score
```

**文件**: 新建 `src/core/quality/normalizer.py`
**替换**: `engine.py:2570-2571`, `content_lock.py:285-294,330-340` 的散点逻辑
**测试**: 3+ 用例 (0-1输入/0-100输入/自动检测歧义边界 `0.5`)

### A2 content_lock 阈值warning + 去重 (2h)

**问题 1.3**: `quality_threshold=1.5` 不会被放大(>1.0), 也不会告警
**问题 3.3**: 相同阈值放大逻辑出现两次(:285 和 :330)

```python
# content_lock.py 合并为 _normalize_threshold() 私有方法
def _normalize_threshold(self, threshold: float) -> float:
    if threshold < 0:
        raise ValueError(f"Negative threshold: {threshold}")
    if 0 < threshold < 10:
        logger.warning(f"quality_threshold={threshold} seems low for 0-100 scale; "
                       f"if this is a 0-1 value, multiply by 100")
    if 0.0 <= threshold <= 1.0:
        return threshold * 100.0
    return threshold
```

**文件**: `src/core/content_lock.py`
**测试**: 正常值/边界1.5/0.5/负数/warning触发

### C1 LLM 实体提取 (3d)

**问题**: 3个提取器均为纯正则, 无法识别不在硬编码列表中的实体

**方案**:
```
当前: rapid_evolver.py 硬编码 13公司+7人+4产品+4缩写
      entity_extractor.py 硬编码模式 + 别名映射 (CATL→宁德时代)
      knowledge_extractor.py 更窄的正则

目标: LLM-based 实体提取 (可选路径)
  路径A: 结构化 LLM 提取 (通用但贵)
    每段文本 → LLM: "识别实体: 公司/产品/技术/人物 > 置信度"
    优点: 0开发, 适应任何领域
    缺点: 成本, 延迟
  路径B: 正则 + 自定义词典 (快速但需维护)
    保留正则, 增加 LLM 定期更新词典
    优点: 快速, 离线可运行
    缺点: 新领域需手动更新
  路径C: 混合 (推荐)
    Phase 1: 用 LLM 做批量实体提取 → 更新词典
    Phase 2: 正则用更新后的词典
    Phase 3: 引入 LLM 做新实体兜底
```

**推荐**: 路径C Phase 1 作为快速启动, Phase 3 作为长期架构

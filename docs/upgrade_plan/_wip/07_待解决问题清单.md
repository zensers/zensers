## 2. 中优先级问题

### 2.1 clear_registry 未清理 hibernate 持久化数据

- **文件**: `src/core/agents/factory.py:434-447`
- **现状**: `clear_registry` 从 `_agents` dict 中删除了agent，但已hibernate到磁盘的数据（通过`self._persistence`）未被清理
- **风险**: 长时间运行的服务中，磁盘上会积累过期session的hibernate数据，造成磁盘泄露
- **建议**: 在 `clear_registry` 中添加持久化清理逻辑:
  ```python
  if hasattr(self, '_persistence') and self._persistence:
      for aid in agent_ids_to_remove:
          self._persistence.delete(aid)
  ```
- **前置条件**: 需确认 `_persistence` 接口是否有 `delete` 方法

### 2.2 _quality_feedback 无类型守卫

- **文件**: `src/core/agents/generic_agent.py:2918-2926`
- **现状**: `for issue in fb_issues[:3]` 假设 `issues` 是 `List[str]`，但如果 `QualityResult.issues` 未来改为 `List[Dict]`（某些历史代码曾假设的），会打印 `{'key': 'value'}` 而非可读文本
- **风险**: 类型变更时静默降级，不报错但prompt质量差
- **建议**: 添加类型检查:
  ```python
  issues_text = "\n".join(
      f"  - {issue}" if isinstance(issue, str) else f"  - {issue.get('message', str(issue))}"
      for issue in fb_issues[:3]
  )
  ```

### 2.3 quality_check_agent.py 融合公式硬编码权重

- **文件**: `src/agents/fixed_agents/quality_check_agent.py:173`
- **现状**: `quality_score * 0.6 + section_overall * 0.4` 硬编码
- **风险**: 不同行业/报告类型的最佳权重可能不同（如深度研究报告可能需要更高section权重）
- **建议**: 将权重提取为配置参数，可在`quality_rubric.md`或session config中覆盖

### 2.4 _extract_quality_score 0-1自动放大的启发式局限

- **文件**: `src/core/orchestrator/execution/engine.py:2570-2571`
- **现状**: `if 0.0 <= score < 1.0: score = score * 100.0`
- **风险**: 这是一个启发式规则，无法完美区分"0.5分/100"和"50%/0-1尺度"。如果上游产生如`0.3`的0-100分数（极少见但可能），会被错误放大到30
- **建议**: 在QualityResult或checkers中显式标注分数尺度（添加`score_scale: Literal["0-1", "0-100"]`字段），消除歧义

### 2.5 agent_session.py AgentSessionStatus 枚举数量 ✅ 已完成(v9.1)

- **文件**: `src/core/agents/agent_session.py`, `tests/unit/agents/test_agent_session.py`
- **现状**: ✅ 测试已更新为 `assert len(AgentSessionStatus) == 7`，与代码一致

### 2.6 _get_professional_role_prompt 方法论注入只取第一个框架且截断150字符

- **文件**: `src/core/agents/generic_agent.py:2910-2911`
- **现状**: `methodologies[0]['content'][:150]` 只取第一个框架，截断150字符

## 4. 架构级观察（非bug，但值得注意）

### 4.1 质量评分双轨制

项目中存在两套质量评分机制:
1. **QualityResult** (checkers.py): 基于规则的关键词匹配 + 0-100分数
2. **QualityCheckAgent** (quality_check_agent.py): LLM-based评分 + 0.6/0.4融合

二者并行运行但互不感知。建议在v10中统一为单一质量评估管线。

### 4.2 retry反馈路径分裂

当前retry反馈通过两条路径:
1. engine.py → `_a._context["quality_feedback"]` (P0-1修复)
2. engine.py → `_a._shared_memory.set("quality_feedback.{agent_id}", ...)` (P0-1新增)

两条路径的数据格式略有不同（context含`previous_attempt`，SharedMemory不含）。建议统一为一个数据源。

### 4.3 prompt方法论注入的3层机制

方法论注入存在3个层级:
1. `_get_professional_role_prompt()` 的 `methodologies[0]['content'][:150]`
2. `{include:quality_rubric}` 共享prompt注入
3. agent skill自身的方法论定义

三层之间没有优先级或互斥机制，可能导致方法论信息重复或冲突。
